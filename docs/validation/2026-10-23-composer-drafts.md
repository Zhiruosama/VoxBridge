# 输出期间编辑下一段草稿

2026-10-23：根据工作台体验反馈，移除主工具栏的“刷新应用”，将手动入口放到设置 → 常规 → 音频 → 监听应用。应用选择下拉框展开时仍自动刷新，原有诊断中的恢复入口保留。

## 输入行为

- 输入框在翻译、准备设备、合成、播放、停止期间均保持可编辑。
- 发送经过配置/长度/设备校验，并占用当前任务后，清空已提交的输入，方便立刻写下一段。仅翻译和独立 preview 路由继续保留原有草稿行为。
- 当前任务仍为单条执行。期间 Enter 不会发送第二条，也不自动排队；Shift + Enter 可换行，输入法组合输入的处理保持不变。
- 每次用户编辑递增草稿版本。提交清空后，旧任务完成不再清空输入；失败或取消只在草稿版本未改变时恢复已提交原文。
- 即使新草稿与上一条逐字相同，或用户编辑后又删除为空，旧任务也不会覆盖它。
- 翻译结果使用提交时的文字与配置快照，仍进入字幕区，不受下一段草稿编辑影响。

## 验证

94 项前端测试通过。新增控制器测试确认 accepted 只在校验通过并持有任务锁后触发一次；配置缺失和重复提交不触发 accepted。

使用当前 App、真实 React 输入事件和模拟 IPC 验证：

1. 工作台没有“刷新应用”，设置中可以找到它。
2. 提交后输入框清空，输出期间仍可输入。
3. 输出期间再次 Enter，语音请求计数保持 1。
4. 新输入与上一条相同的内容，上一条完成后仍保留。
5. 失败后保留已编辑的新草稿；未编辑时恢复原文。

模拟测试未读取密钥、未调用付费服务或发送实际音频。生产前端构建、格式检查、macOS .app 打包与严格签名校验通过。没有修改 Rust 音频管线。当前已运行的软件不自动重启，避免中断体验或清空会话密钥；新行为在下次启动打包应用时生效。
