# macOS 悬浮窗跨屏拖动修复

[验证索引](README.md) · [当前使用指南](../user-guide.md)

> 历史验证记录：仅说明记录日期的测试范围，不代表所有平台、客户端或后续构建均通过。

## 问题与改动

用户报告将悬浮窗拖到另一块显示器时跳闪。原实现把 WKWebView 的 `screenX/screenY` 差值直接加到 AppKit 窗口位置；跨显示器时浏览器屏幕坐标与 AppKit 全局逻辑点并非可互换的坐标空间，尤其不能依赖不同 backing scale 下的坐标连续性。

现在前端只发送拖动开始、移动、结束的通知，继续合并在途更新。macOS 在开始时同时记录窗口原点和 `NSEvent.mouseLocation()`，后续使用同一全局坐标系的原生鼠标位移计算新原点。Windows 仍使用 `start_dragging()`，不引入手工坐标计算。保留拖动 ID 隔离与取消/丢失捕获后的结束处理。

涉及 `src/hooks/useOverlayDrag.ts`、`src-tauri/src/overlay/panel.rs`、macOS 的 NSEvent crate feature。没有修改系统显示设置或要求辅助功能/录屏授权。

- 新增原生坐标测试：鼠标偏移在右侧、左侧负坐标、上方和下方显示器位置及拖回起点时保持一致。
- 格式检查、Mac app 构建及签名/麦克风 entitlement 检查通过。
- 本机应用已更新启动；悬浮窗打开与同步正常。

- 自动 UI 拖动没有产生可确认的跨屏窗口位移，不能把该尝试记作跨屏拖动实测通过。真实鼠标连续跨越 2×/1× 屏幕边界、反向拖回及全屏桌面切换仍需用户体验确认。
