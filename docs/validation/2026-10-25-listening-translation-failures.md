# 单句译文校验失败导致监听停止

## 证据与范围

- 本机诊断记录在 2026-10-25 21:50:56、21:52:02（UTC+8）各有一次 `start_listening / error / invalid_response`，持续约 78 秒、42 秒。
- 两次终止前最后一次翻译指标均为 queued=0、inflight=1，没有显示翻译队列积压。诊断记录不包含原文、译文或服务响应，不能还原具体错误回复。
- 用户截图显示译文校验重试后仍失败，目标为简体中文、返回语言识别不确定。这个提示只表示返回内容未通过校验，不表示印尼语不受支持。
- 代码确认：服务层已把语言说明附加到 `INVALID_TRANSLATION` 后，实时字幕处理仍用整串相等判断可隔离的单句错误，导致带说明的错误上抛并结束监听。HTTP 分段路径也直接上抛此类错误。

## 修复

- 使用同一个判断识别无效译文错误，兼容无说明和有说明两种形式。
- 实时和 HTTP 分段监听均把这种错误显示为当前句翻译失败，继续处理后续字幕。
- 保留目标语言校验与现有一次重试；密钥、配置和其他服务错误仍按原逻辑处理。
- 未修改原文/译文日志策略，未录制频道音频，未调用收费服务。

## 验证

- 模拟带“目标：简体中文；返回语言识别：不确定”的实际错误，验证下一句仍完成翻译。
- 模拟 HTTP ASR 与翻译回复，验证连续两次返回印尼语原文后只产生该句 `translationError`，处理函数正常返回。
- 验证服务配置错误仍结束任务，避免无限吞掉错误。
- 验证截图中的印尼语短句原文不被当成中文译文，中文翻译和原样域名可以通过校验。
- Rust 单元测试：146 通过，23 项需要真实服务/硬件的手动测试跳过；严格 Clippy 通过；Windows 安装包构建通过。

真实频道中的识别准确率、模型对口语片段的翻译质量仍需要用户继续试听验证；本次修复不保证每句模型输出都有效。

## Mac CI 后续修复

首次推送后的 Check（40204183927）在 Mac 失败：`Batak.com.` 原样保留的断言未通过。Mac 的系统语言识别会给这个标识判定语言，先于域名保留规则拒绝它；Windows 的识别结果不同，因此本机测试通过没有覆盖这个平台差异。

修复为在语言识别前识别完全未变化的独立域名。例外仅适用于规范的 ASCII 域名标签与句尾标点，不接受普通口语、邮件地址、路径或模型另行返回的域名。保留原来的失败测试，并增加有效/无效标识边界用例。Windows 本机 147 项测试通过，严格 Clippy 通过；Mac 与 Windows ARM64 的结果由此次推送后的 CI 确认。
