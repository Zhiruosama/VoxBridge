# Windows 与 Mac 后端对齐

[验证索引](README.md) · [Windows 待办](../windows-development-todo.md)

基线：主分支 `4e91db3`（v0.4.0 后的启动与主题修复）。本次只补平台后端差异，不修改音频设备默认值、服务配置、密钥或驱动。

## 审核结果

| 功能 | 当前实现与差异 |
| --- | --- |
| 翻译、HTTP/实时 ASR、TTS、MiniMax 高级参数 | 共用 Rust 业务与命令，Windows 已包含 v0.4.0 新功能，无需另写适配器 |
| 准备/播放/丢弃语音、发送队列、服务测试 | 命令与窗口 ACL 均已接入；失败队列项不阻塞后续请求 |
| 凭据与更新 | 共用加密模板和签名更新；Mac 系统保护与 Windows 当前用户 DPAPI 分别实现 |
| 应用采集 | Mac Core Audio 与 Windows WASAPI 原生采集不同，均输出相同 PCM/识别管线；Windows 只按明确的暂时故障恢复 |
| 短文本语言识别 | Mac 使用系统 NaturalLanguage；Windows 原 Whatlang 不能通过同一组常见聊天回归，本次补离线短文本模型 |
| 设备枚举 | Mac 已跳过中途断开的单个设备；Windows 本次补同等容错，并统一输出/麦克风完整名称 |
| 悬浮窗 | Mac 使用原生面板处理 Spaces 与全屏，Windows 使用 Tauri 原生窗口及系统拖动；无需把 AppKit 修复复制到 Windows |
| 虚拟麦克风 | Mac 自有音频设备与 Windows VB-CABLE 是不同驱动；Windows 端点改名不等于实现了自有驱动 |

## 本次补齐

- Windows WASAPI 激活、格式初始化、事件/缓冲准备和启动阶段，识别设备失效、资源失效、音频服务未运行的 HRESULT，并交给已有的有限次数退避恢复。拒绝访问、不支持格式和未知启动错误不会盲目重试，不输出系统原始错误内容。
- 输出设备列表跳过枚举后已断开或属性读取失败的单个端点；枚举器本身失败仍返回错误。稳定 ID、同名歧义拒绝和指定设备不回落的规则保留。
- 麦克风与输出设备共用完整名称选择，优先 WASAPI 扩展名称；录音设备仍过滤 VB-CABLE/VoxBridge 回送端点。
- Windows 对低置信度 Whatlang 结果使用 Lingua 离线短文本识别；只编译九种受支持语言及法语排除模型，按需加载并复用。高置信度的不支持语言仍返回不确定；混合文字系统在识别前排除。模型仍可能有误判，不承诺与 Mac 的每个输入得到相同结果。
- 两组原仅 Mac 执行的语言回归改为两端执行，并增加混合文字与不支持语言回归。语言识别 IPC 移到阻塞工作线程，避免首次加载阻塞窗口事件处理。

## 验证边界

- Windows 本机：154 项默认 Rust 测试通过，24 项手动测试保持默认忽略；`cargo clippy --all-targets -- -D warnings` 与格式检查通过。
- 单独运行只读硬件检查：5 个输出端点稳定 ID/完整名称解析通过，2 个实体输入端点的稳定 ID/名称与回送过滤通过；没有打开输入/输出流。
- 前端 227 项测试、生产构建、文档检查及 5 项发布脚本测试通过。

测试使用固定文本、模拟错误和只读设备枚举，不调用收费服务、不打开麦克风、不更改系统音频服务。真实热插拔、睡眠唤醒和长时间通话仍按平台待办单独验收；模拟 HRESULT 不能代替这些实机验证。Mac 原生识别保持原实现，由跨平台 CI 检查回归。
