# 2026-10-23 显式模板授权与本次密钥

用户要求：只能在设置中申请一次系统密码；本次打开期间不再请求权限。空白配置和手动输入不得读取已有模板，也不得自动切到其他已保存服务。本轮替代旧版“运行服务时读取 Keychain”的方案。

## 行为

- 手动输入 API Key 后点“本次使用”，或随普通配置保存：只写 Rust 内存，不查询钥匙串，不持久化密钥。真实翻译 / ASR / TTS 也只读这份内存，缺失就提示回设置，绝不回退到 OS 存储。
- “保存为模板”显式保存当前非敏感连接配置，并将密钥加密到应用数据目录的 `credentials.v1.enc`。整个文件使用 AES-256-GCM、每次写入随机 nonce，OS 凭据存储只持有一份随机加密主密钥。后续保存只用本次内存主密钥，不再访问 OS。
- 下次打开应用，模板默认为锁定状态。只有设置中的“解锁模板”按钮会请求读取主密钥，一次解锁所有模板。解锁不会切换当前服务，也不会覆盖已手动输入的本次密钥。
- 整个进程只有一个授权入口和一次尝试额度；在调用 OS 前消耗额度。取消、拒绝、损坏文件、并发点击都不会引发再次申请。失败后仍可手动输入使用；重新申请需重启应用。
- 首次没有模板时，普通查看 / 输入 / 调用不创建主密钥。“保存为模板”才创建；空密钥保存请求在访问 OS 前拒绝。
- 正常退出清空内存，密钥和主密钥用 zeroize 包装。密钥不会返回前端或写入普通 settings JSON；模板文件通过私有临时文件原子替换。
- 当前配置为空或活动标识不存在时创建独立空白配置，不挑第一份已有模板。默认地址 / 模型 / 音色均为空。“新建空白配置”使用新标识，不继承旧模板字段或密钥。
- 连接参数草稿由主应用持有，切换分类、返回字幕页再回来不丢失当前草稿。保存普通配置后才持久化；手动密钥仍默认仅本次有效。

## 兼容边界

旧版非敏感配置继续保留。旧 Keychain 中分散存放的 API Key 不自动读取或迁移，也不删除；用户首次使用新模式时需手动输入，并可显式保存为加密模板。这避免为了迁移多个旧条目而连续弹出系统密码框。历史付费测试的旧凭据读取改为明确的 test-only helper，不编译进正式应用，默认测试不调用。

## 验证

前端 72 项、Rust 71 项默认测试通过（15 项历史硬件 / 付费测试默认忽略）。严格 Clippy、格式和 Mac `.app` 构建 / 签名检查通过。

新增回归覆盖：

- 内存手动输入 / 读取 / 清除不消耗授权、不创建磁盘文件；缺失密钥不会触发 OS 查询。
- 取消授权后不可再次申请，手动密钥继续可用；两个并发解锁只有一个可以进入 OS 边界，等待授权不阻塞手动使用。
- 加密文件往返、写入内容不含明文密钥、重复保存不再次授权、篡改密文拒绝解密、重启后锁定、手动输入不被模板覆盖。
- 损坏文件不触发 OS 授权；不重试损坏文件。
- 空配置 / 活动标识缺失不选择已有模板，空阶段创建独立配置，不完整的手动连接参数得以保留。

本轮没有真实读取旧钥匙串、创建真实加密主密钥或调用供应商。OS 访问边界通过注入的测试实现验证计数；加密和文件写入使用真实实现。真实首次主密钥创建 / 解锁的系统确认保留给用户在设置中显式操作，不代替用户点击授权提示。
