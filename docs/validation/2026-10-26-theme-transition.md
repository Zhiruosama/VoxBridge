# Mac 主题切换中断与备用动画

[验证索引](README.md) · [外观设置](../guides/appearance.md)

## 问题与修复

基线 `4e91db3` 在所有主题模式下监听 `prefers-color-scheme`。Mac 还会通过 `setTheme()` 同步原生标题栏；如果 WKWebView 因此发送颜色变化通知，监听器会重新执行 `apply()`，取消正在播放的 View Transition 或移除旧画面层。Windows 自定义标题栏没有这次原生调用。这是可由模拟原生通知重现的中断路径，不代表已经在每个 Mac WebView 版本上观察到相同事件行为。

现在只在“跟随系统”时监听，并且忽略已应用颜色的重复通知；快速切换时也在原生主题调用返回后检查代次，避免旧请求再写入背景。

不支持 View Transition 的 WebView 原先还会复制整个界面，再交替读写每个元素的滚动位置，并立即开始动画计时。这会增加布局开销，且繁忙时可能在旧画面首次绘制前消耗动画时间。本次改为先批量读取，再写入副本，经过两次 `requestAnimationFrame` 后才更新主题、开始淡出与计时。副本保存输入框/文本域/选择器当前值、滚动位置、旧主题颜色，并保持 inert、无障碍隐藏和不可交互。

Windows 支持的浏览器快照路径保持原有过渡；未改变色板或刻意延长切换时间。减少动态效果的偏好仍在切换前生效。

## 验证范围

- 前端 227 项测试通过；新增模拟 Mac 原生主题回调、真实系统主题变化、重复通知不取消动画、绘制后计时、滚动/草稿保留、快速切换取消等回归。
- TypeScript 与 Vite 生产构建通过。
- 本机原安装包为 0.3.0，因此原 Windows 安装版与新 Mac 版本的视觉比较还包含版本差异。
- 当前机器为 Windows，未做 Mac WKWebView 的实机动画观感或帧率验收；Mac 原生标题栏不能参与 DOM 快照动画，也不承诺标题栏与页面逐帧相同。
