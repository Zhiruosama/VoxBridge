# 悬浮窗缩放热区

[验证索引](README.md) · [外观设置](../guides/appearance.md)

无边框透明窗口的可见边缘与原生窗口边缘之间有留白，单靠系统细窄的缩放区域不容易抓取。本轮在网页四边增加 12 CSS px、四角增加 22 CSS px 的透明命中区域，覆盖留白与可见边缘；提供方向指针，不加粗可见边框，也不覆盖内部按钮和输入文字。

macOS 命令只控制实际承载字幕的 NSPanel，不修改隐藏的 Tauri 宿主。原生主线程采样 AppKit 全局逻辑坐标，以手势开始时的框架计算尺寸，固定对侧锚点，保持最低 480 × 220 逻辑点。尺寸变化不使用浏览器屏幕坐标，不累积移动误差。原有顶部移动逻辑保留；切换手势、隐藏窗口时清理状态。Windows 路径交给原生窗口缩放，仍需 Windows 实机验证。

缩放命令仅授权字幕窗口，校验调用窗口、手势标识、阶段和八种方向；没有增加文件、凭据、录音或网络权限。

## 验证

- 250 项前端测试通过，包括八个方向的命令路由、等待开始响应时合并移动事件、丢失捕获后只结束一次、卸载清理与原有拖动路线。
- 168 项 Rust 测试通过，23 项手动测试未运行。几何回归覆盖八个方向、最小尺寸、负坐标屏幕位置、反向拖回与固定对侧锚点。
- [`overlay-resize-regression.rs`](../../src-tauri/examples/overlay-resize-regression.rs) 创建一次性不可见 NSPanel，复用生产内容迁移及缩放几何，验证八个方向的原生尺寸与迁移后根视图尺寸一致，隐藏宿主保持有效。无用户录音、模型调用或用户窗口移动。
- 前端构建、格式、文档检查和 Mac App 打包签名检查通过。

边缘命中范围由 CSS 固定逻辑像素定义；真实多屏拖动手感、不同显示缩放与 Windows 原生行为仍需用户体验。自动测试不代替这些实机观察。
