# 日常密钥持久化

[验证索引](README.md) · [当前使用指南](../user-guide.md)

> 历史验证记录：仅说明记录日期的测试范围，不代表所有平台、客户端或后续构建均通过。

用户保存密钥后，后续启动自动恢复。此行为取代此前“本次使用，退出清除”的默认策略；模板仍为单独、显式操作。

## 行为与存储

- “保存密钥”和设置页带有新密钥时的“保存更改”均持久保存当前配置的密钥。已解锁模板中的密钥也可直接点击“保存密钥”，不必重新输入。
- 日常密钥使用独立的 `saved-credentials.v1.enc`，复用 AES-256-GCM、随机 nonce、认证文件头、原子替换和 Unix `0600` 权限。主密钥存放系统凭据存储，不进入普通配置或 localStorage。
- 启动只恢复日常文件，macOS 使用禁止授权界面的 Keychain 查询。恢复完成后，翻译、识别、语音和配置修改都读取内存；后续保存复用缓存主密钥。
- 系统钥匙串锁定、访问权限变化或文件损坏时，保留原文件，在设置中显示错误。不会在启动时弹密码窗口，也不会覆盖成空文件。显式保存可申请系统授权；失败后本次不循环请求。
- “移除保存的密钥”同时删除日常文件中的对应条目和当前内存条目，重启不会恢复该条目。其他配置不受影响。
- 旧模板 `credentials.v1.enc` 不会自动读取或应用。仅选择相同配置标识的已保存密钥，不切换当前配置，不给空白配置套用模板。
- 旧版仅在内存中的密钥需在新版保存一次；不能从已退出的旧进程恢复。应用代码签名变化可能需要在设置中重新授权保存，禁止通过放宽 Keychain ACL 绕过系统保护。
