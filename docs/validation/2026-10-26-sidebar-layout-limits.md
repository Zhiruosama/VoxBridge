# 侧栏拖动与主窗宽度限制

[验证索引](README.md) · [外观说明](../guides/appearance.md)

## 原因和改动

旧侧栏限制只为主区保留约 400 px；底部 composer 在内容宽度不超过 700 px 时切成两行，导致侧栏拖宽后工具栏改变布局。

- 共享侧栏限制现在为主区保留至少 780 逻辑像素，另计 shell 的 16 px 内边距与 6 px 列间距。扣除输入区内边距和边框后仍高于 700 px 分行断点。
- Mac 与 Windows 主窗口最小宽度均为 1000 逻辑像素；默认窗口大小、最小高度和字幕浮窗尺寸不变。
- Windows 默认 1062 px 窗宽下，侧栏最多 260 px；宽窗仍可使用原来的 360 px 上限。原来保存的侧栏偏好只在渲染时按当前窗宽收紧，不清空服务配置或密钥。
- 浏览器窄窗口仍保留原有响应式后备布局；桌面主窗不再允许缩至会挤压工具栏的宽度。

## 检查

231 项前端测试及 TypeScript/Vite 生产构建通过。边界回归同时读取两端 Tauri 配置，检查最小主窗、默认主窗与宽窗下主区和 composer 的剩余宽度。

Windows 实际窗口拖动和最小宽度验收以安装后的检查为准；当前机器无法验收 Mac 原生窗口拖动。

## 文本翻译页补充

文本翻译页原先在容器不超过 660 px 时切成上下排列，早于两块最小 240 px 面板与 18 px 分隔条真正放不下的边界。现在使用独立的具名容器查询，在 540 px 以下才启用窄屏后备布局；桌面侧栏拖动不应触发它。

侧栏的 grid 列宽及拖动柄还增加相同的 CSS 限宽，使用共享的工作区最小宽度。这样即便 ResizeObserver/React 尚未响应缩窗，旧的 360 px 偏好也不会先把主区挤窄。回归同时检查最小桌面窗口、旧侧栏偏好、翻译页内边距/边框及滚动条所需空间。232 项前端测试与生产构建通过。
