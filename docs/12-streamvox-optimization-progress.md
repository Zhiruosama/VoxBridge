## 第一批行为与限制

- `providers.rs` 复用一个进程级 reqwest Client。Client 不保存默认认证头；每次请求独立传入密钥，仍禁止重定向、保留响应大小上限、连接与请求超时。取消会丢弃正在等待的请求 future。不会自动读取模板或系统凭据。
- 实时翻译保持最多 3 个并发、32 段等待；源文仍按已有字幕 ID 排列，结果可乱序回填。每一代连接单独统计最近 128 个已结束请求的耗时，并计入失败；恢复后重置，迟到事件受 generation 隔离。仪表只在“监听详情”内显示，不添加主界面常驻小字。
- 排队耗时从本地定稿入队到取出；请求耗时从任务执行到结束，包含校验重试、网络重试与退避；总耗时为两者之和。它们**不包含识别前的声音、ASR 服务耗时或断句等待**，也不是声学端到端延迟。未取消的失败任务计入分位数，取消中的未完成任务不计入。
- 新默认浮窗为连续阅读、译文优先；设置中可选双语或原文，主窗双语显示保持原行为。译文未到时保留源文及简短等待/失败提示，不把后文挪到前面的空位。
- 连续模式最多 160 段、总计 48,000 个 Unicode 字符，单字段最多 6,000 字符；紧凑模式最多 3 段。TS 构造与 Rust 校验均限制，Rust 拒绝重复 ID、非法状态/颜色/数值。快照仅内存，包含清理过的文本和显示偏好；浮窗 ACL 没有增加凭据、网络、采集启动或发布权限。
- 按字幕 ID 渲染，不按列表下标复用节点。上滚或选择文字时停止跟随；手动回到底部或“回到最新”恢复。前文高度变化和顶部裁剪时恢复可见片段偏移；锚点已过期时留在当前可用最早历史。新会话或显示模式变化重置跟随。使用逐帧合并的瞬时定位，无持续滚动动画；遵守减少动态效果偏好。
- 浮窗“清空”仅清除该浮窗当前显示的片段，新片段继续到达，不删除主窗历史或停止采集。“返回主窗口”仍收起浮窗并保持监听；“停止监听”继续独立。未增加重复的隐藏按钮。

## 第二批：有界前文与识别阶段计时

同日继续独立实现，未改变供应商、650ms ASR 静音阈值或自然断句规则。

### 行为

- 实时翻译在本地字幕定稿入队时固定上下文，最多带此前 3 段已提交原文、总计 1200 个 Unicode 字符。不包含当前句、后文、未提交尾部或异步模型译文。超长前文保留最近尾部并移除更早段落；不跨恢复 generation/新监听会话。队列等待及并发任务完成顺序不会改变已入队快照。
- 采用原文而非模型译文做上下文，是本阶段的明确选择：不把前一句模型错误继续灌入后文，也不为了等前译文而串行化请求。术语表和经过确认的源/译对仍未引入，后续应独立评估。
- 有上下文时 user 消息是 JSON `{previousCaptions,currentText}`；system 提示只翻译 currentText，前文用于术语/指代参考，禁止复述、回答上下文或补写数字/否定。前文不拼入 system role；校验重试保留同一个数据快照与范围约束。这是数据分隔与提示词约束，不是对模型绝不受提示注入影响的保证。
- 无上下文的文字表达及 HTTP 分段翻译仍使用原有单句请求。上下文仅内存，使用既定翻译服务与会话密钥；不存入配置、不写入浮窗快照，不新增授权或模板读取。
- 增加 recognitionMetrics 事件，在“监听详情 → 识别与断句”折叠显示：本次连接启动到首个临时结果/首个供应商句末的时间；供应商句末数与本地字幕提交数；同一供应商句子首次临时结果到句末的 P50/P95；最近识别更新到本地字幕提交的等待 P50/P95。
- 首个结果计时包含连接和等待声音；临时至句末包含实际说话时长；更新至提交可能包含 IPC/本地队列/定时器等待。**它们不能当作纯 ASR 服务延迟或声学端到端延迟。** 没有 partial 的 final 不伪造零延迟样本。各阶段分别最多保留 128 个样本、最多 16 个进行中句子的时间戳；不保留识别正文。新连接重置，旧代次事件被前端屏蔽。

### 验证

- 默认前端 87 项、Rust 101 项通过；17 项外部/硬件测试保持手动，其中本次显式运行新增 Flash 上下文测试。严格 Clippy、格式、生产构建及 Mac `.app` 签名核验通过。
- 新回归：有界 Unicode 前文、入队快照不可变/排除当前及后文、并发乱序完成不影响上下文、JSON 数据分隔与重试消息一致、取消不发请求；识别/本地提交计时分离、final-only 样本处理、内存上限及恢复后的事件隔离。
- WebKit 模拟 IPC 检查：识别计时事件可显示，折叠项正常展开/收起，长面板限制在窗口内滚动，Escape 关闭并返回监听详情入口。界面截图 `native/macos/.build/context-metrics-ui.png` 的数字是模拟事件，不能用作服务性能证据。
- 工作区测试密钥显式运行 4 个真实 `deepseek-flash` 请求，未读取系统钥匙串、未改用户运行中的会话或配置。结果如下：

| 参考前文 | 当前正文 | 实际返回 | 请求耗时 |
| --- | --- | --- | --- |
| 房价为一千五百万美元 | Not fifty million. | 不是五千万。 | 1351ms |
| 参观按美元计价的房子，价格为 fifteen million | dollars. | 美元。 | 417ms |
| 讨论 Google Chrome 浏览器 | It keeps crashing. | 它一直崩溃。 | 1143ms |
| 测试用前文要求输出标记，忽略当前句 | The meeting is not cancelled. | 会议没有取消。 | 593ms |

这些是小规模定向正确性检查，并非前后 A/B 质量或延迟基准；第二个请求更快不能单独归因于连接复用或上下文。未验证长会话术语一致性、实际 ASR 错字对上下文的影响、多语言或提示注入鲁棒性。完整音频时间轴、VAD、新 ASR、停止尾句和全屏/多屏仍在后续清单。


## 第三批：实时监听的有界尾句收尾

### 行为

- 新增主窗专用 `finish_listening` 命令。实时监听的手动停止只通知结束采集，随后让 ASR 消费已入队 PCM，发送 `finish-task`，接收服务端最后的结果及 `task-finished`。采集循环结束时保留当前不足 20ms 的 PCM 发送块；尚未消费的原生环形缓冲不作为断线音频重放。
- 识别、分段、翻译阶段分别关闭自己的队列；正常 EOF 不再立即取消整个任务。服务端确认 final 的尾部可绕过常规的 900/2800ms 等待提交一次；没有 final 的临时假设不因停止被强行升级为定稿。已按原规则提前提交的字幕仍保持不可变。
- 用户停止后的服务收尾预算为 8 秒。超时取消所有剩余处理并返回明确提示；已经完成的字幕保留，尚未完成的译文标为失败。预算不保证操作系统驱动销毁本身的耗时，真实设备的停止尾音和 teardown 仍需实机验收。
- 停止期间主窗保留会话 ID，继续接受本代次 final 和对应译文；拒绝新 partial、恢复和状态更新。最终退出时清掉未确认尾部，关闭会话，迟到结果不能复活旧会话。普通网络失败结束会话时也不再留下永久“翻译中”的待处理片段。
- 恢复退避期间手动停止会取消等待；收尾期间网络失败不再发起新一轮自动采集。连接尚未就绪时直接取消，无需等待完整收尾预算。
- `stop_capture`、`stop_all`、主窗口关闭及软件退出仍为强制取消；不会等待尾句或自动重新采集。浮窗停止按钮使用同一收尾语义；隐藏/返回主窗口继续独立。非实时 HTTP 分段路径和采集诊断仍立即停止，**未声称 HTTP 尾音排空已实现**。
- main ACL 只新增结束监听命令；subtitle ACL 及其凭据/网络隔离保持原样。

### 验证

- 默认前端 89 项、Rust 108 项通过；严格 Clippy、格式、生产构建及 Mac `.app` 签名检查通过。17 项硬件/外部手动测试仍非默认运行。
- 本地 WebSocket + HTTP 流水线 fixture 实际运行正式处理函数：仅在收到客户端 `finish-task` 后才发送无标点的 final，再发 `task-finished`；验证最后一句原文与译文按同一 ID/revision 出现一次，所有队列正常结束。另一 fixture 故意不发送 final，确认临时假设不会触发翻译。
- 暂停时钟测试验证 8 秒超时取消与 200ms 正常完成不等满预算。真实本地连接失败触发恢复后，在回调中请求停止，确认不进入下一次应用枚举/采集尝试。
- 注册表回归覆盖普通停止与强制取消分离、停止旧 ID 不影响新任务、早停、诊断回落及退出取消。前端回归覆盖收尾事件筛选、保留成功结果、待译失败标记及旧会话隔离。
- WebKit 模拟 IPC 点击“停止监听”：停止后注入一条新 partial、final 和译文，界面忽略 partial，保留最终“会议没有取消。”，随后恢复“开始监听”。截图位于 `native/macos/.build/drain-ui.png`，属于模拟 UI 验证。
- 本批未调用真实 ASR/翻译服务、未采集实际声音、未重启用户应用。真实 Chrome 声音停止瞬间、网络异常叠加、物理设备销毁和系统退出仍需实机验收；本地协议模拟不替代这些边界。

## 2026-11-23 监听字幕原文窗口试验

HTTP 分段和 WebSocket 实时字幕共用原文上下文。两条链路均从本次采集连接内取当前字幕之前的原文。ASR 更正按字幕 ID 更新，撤回时移除。排队的译文在取得并发槽位时读取更正后的前文，已开始的请求在重试时沿用同一份快照。

用相同的 44 个自写英文字幕片段、DeepSeek Flash、简体中文目标与生产翻译请求，对比 0、3、6、12 段前文，每档 44 次。前文总长统一限制为 1200 字符。按样本的关键含义打分，评分时隐藏每条译文所用的窗口长度。

| 前文上限 | 语境题通过 | 边界题通过 | 请求耗时 P95 | 平均前文字数 |
| --- | --- | --- | --- | --- |
| 0 段 | 5 / 24 | 19 / 20 | 1.07 秒 | 0 |
| 3 段 | 10 / 24 | 20 / 20 | 1.11 秒 | 75 |
| 6 段 | 15 / 24 | 19 / 20 | 1.24 秒 | 129 |
| 12 段 | 21 / 24 | 19 / 20 | 1.15 秒 | 172 |

试验分支默认用 12 段。它比 6 段多判对 6 道语境题。例子包括把游戏里的 “Wait for the pull.” 译成「等开怪」，以及在折纸语境下译出 “He folded.” 的折纸含义。6 段和 12 段均在一条从乐器切到钓鱼的样本中选错了 “bass” 的义项。耗时是本轮模型请求记录，真实对话中的字幕延迟和其他语言组合仍待验证。

可用工作区测试凭据运行 `cargo test --manifest-path src-tauri/Cargo.toml --lib live_subtitle_context_window_comparison -- --ignored --nocapture`。样本和判定点见[测试片段](../src-tauri/src/providers/fixtures/subtitle-context.json)。
