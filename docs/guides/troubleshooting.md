## 翻译或服务请求失败

1. 在对应服务设置页确认当前配置、接口地址、模型和已保存的 API Key。
2. 如果刚输入新密钥，先点击「保存密钥」；配置修改还需要「保存更改」。
3. 手动点击服务测试。ASR 的本地配置检查不能替代实际短音频识别测试。
4. 按提示处理：网络恢复后重试；限流时稍等；余额不足时检查供应商账户；模型或音色无权限时换成账号可用的配置。

独立文本翻译可「重试上一条」，不会覆盖新草稿；等待超时会保留内容。发送队列失败项也可单独重试。若队列已暂停或因停止输出而暂停，需要点击「继续」。

重新提交可能计费，不建议连续点击测试或反复自动重试。私人克隆音色可能受账号权限限制，第一次生成还可能涉及厂商音色费用。

## 声音输出与设备

- **发送设备**决定声音进入虚拟麦克风还是其他输出；选成耳机时，对方不会收到。
- **试听设备**决定自己听到什么。关闭耳机按钮后，本地安静不代表发送失败。
- 耳机经常插拔时，试听选择「系统默认」。手动绑定的设备断开后，不应期待程序悄悄换到另一个设备。
- 刷新设备后重新选择，确认没有其他软件独占设备。
- Discord 测试中断续或失真，可尝试工作室配置，并避免 VoxBridge 试听和 Discord 回放同时开启。

没有生成语音时虚拟麦克风保持安静，Discord 的“未检测到输入”提示本身不说明故障。

路由对照见[语音输出指南](voice-output.md#先确认声音发到哪里)。

## 聊天软件看不到虚拟麦克风

Mac 查找 **VoxBridge**，Windows 查找 **CABLE Output**；如果自行修改过 Windows 显示名，选择对应设备。

确认驱动已安装，按驱动要求重启电脑，再完整退出并重新打开聊天软件。网页端需要对应的麦克风授权。不要只关闭设备菜单后就假设客户端已重新枚举。

QQ、微信兼容性仍有环境限制。QQ 曾在临时兼容设备与重启后列出设备，但该临时方案不代表普通安装可用；微信也不能保证所有环境均可识别。进展见 [issue #1](https://github.com/Zhiruosama/VoxBridge/issues/1)。需要技术细节时再看[兼容性调查](../wechat-virtual-microphone-investigation.md)。

## 监听与权限

系统音频访问和实体麦克风访问是不同权限。只翻译文字不需要录音；主动录音时才使用实体麦克风。

应用列表没有目标时，重新展开列表或在设置中刷新应用，并确认目标应用仍在运行。没有字幕时，先确认它正在发声、识别服务已配置，再检查系统音频权限。

Mac 测试包采用临时签名，重新构建或更新后系统可能再次要求确认权限，不能由软件直接跳过。Windows 的「需要在系统设置中确认」表示无法确定授权状态，应检查麦克风访问和允许桌面应用访问。

监听会尝试从部分网络或采集错误恢复；手动停止后不会自行恢复。多人发言、噪声、模型不支持的语言和断句均可能影响结果。

## 保存、更新与隐私

密钥保存后重启应能继续使用；若丢失，先确认是否换了系统用户、电脑、安装位置关联的数据环境，或卸载时主动清除了数据。不要把密钥贴到截图或问题正文中。

文本翻译草稿、结果和发送队列仅保留在本次运行期间，退出会清空；它们与持久保存的服务配置不同。更新前先保存要保留的文字并结束音频任务。

云服务可能收到你提交的文字或音频。诊断日志仅在本机保存，不记录密钥、录音或字幕正文，但反馈前仍应检查截图与附件。

## 导出诊断信息

在「设置 → 音频与诊断 → 本机诊断日志」导出日志，附上：

- 系统与架构，例如 Apple Silicon Mac 或 Windows x64。
- 出现问题的操作步骤、发生时间和错误截图。
- 使用的服务、模型、音频设备名称；不要提供 API Key。

到 [GitHub Issues](https://github.com/Zhiruosama/VoxBridge/issues) 反馈。日志字段和轮转方式见[诊断日志说明](../diagnostics.md)。
