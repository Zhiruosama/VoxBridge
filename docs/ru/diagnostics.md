# Локальные журналы диагностики

[Руководство пользователя](user-guide.md) · [Внутренние процессы, 中文](../internal-flows.md) · [Разработка, 中文](../development.md)

Журналы помогают разобраться с ошибками операций, переподключениями, остановкой очереди и временем выполнения этапов. Это не облачная аналитика.

## Как предоставить журнал при ошибке

1. Сохраните снимок ошибки, запишите примерное время и последовательность действий.
2. Откройте «Настройки → Звук и диагностика → Локальные журналы диагностики» и нажмите «Экспортировать журналы».
3. Приложение создаст `VoxBridge-diagnostics.jsonl` и откроет его папку. Просмотрите файл и приложите к сообщению об ошибке.
4. Укажите версию приложения, версию ОС, архитектуру процессора и использование виртуального микрофона. Не отправляйте ключ API или весь каталог данных приложения.

Экспорт читает только три файла журналов этой функции. В него не входят конфигурации сервисов, каталог ключей, записи аудио и история переписки. Файл сохраняется в подкаталоге `export/` папки журналов. Каждый экспорт заменяет предыдущий; для нескольких снимков сначала скопируйте предыдущий файл в другое место.

«Открыть папку журналов» показывает исходные ротируемые файлы. Путь по умолчанию на macOS:

```text
~/Library/Logs/com.voxbridge.desktop/diagnostics/
  diagnostics.jsonl
  diagnostics.1.jsonl
  diagnostics.2.jsonl
  export/VoxBridge-diagnostics.jsonl
```

Фактический корень определяется функцией Tauri `app_log_dir`. Открытие папки и экспорт разрешены только главному окну. Плавающие окна могут добавлять лишь метаданные из разрешённого набора и не могут читать журналы.

## Что записывается

| События | Содержимое |
| --- | --- |
| Запуск, обычный выход, Rust panic | Версия приложения, платформа, архитектура, ID запуска, тип события; без сообщения panic и стека |
| Перевод, ASR, запись, TTS, запросы устройств и конфигурации | Начало, завершение, длительность, случайный ID запроса, фиксированный тип протокола, категория ошибки |
| Восстановление прослушивания | ID сеанса, номер попытки восстановления, задержка, категория устройства или сети |
| Потоковые субтитры | Число завершённых фраз, успешных и неудачных переводов, очередь, активные запросы, P95; не чаще одного сводного события каждого типа за 5 секунд |
| Вывод речи | Синтез, декодирование, ожидание устройства, начало воспроизведения, завершение и время от начала операции |
| Очередь отправки | Изменения состояния, количество задач, пауза, продолжение, отмена, завершение; без повторной записи одинакового состояния |
| Интерфейс и локальные настройки | Открытие страниц, смена темы, успех и ошибки сохранения/чтения; без значений настроек |
| Необработанные ошибки интерфейса | Тип события и категория ошибки; без исходного текста, пути файла и стека |

Сведения о прослушивании также показывают уровень моносигнала после сведения, число кадров около максимального уровня, число участков со значительно меньшим уровнем после сведения, недавние исправления субтитров и расхождения с итоговыми фразами поставщика. Близость к максимальному уровню не доказывает клиппинг, а низкий уровень сведения — только диагностическая подсказка. Эти данные не вызывают автоматическую смену каналов или усиления.

Для `recognition_corrections` поле `count` означает число исправленных субтитров текущего подключения, а `failedCount` — количество итоговых фраз поставщика с недавними расхождениями. Для `audio_quality` те же поля означают кадры около максимального уровня и участки с низким уровнем после сведения. Здесь `failedCount` — счётчик категории, а не ошибок запросов. Замер выполняется не чаще раза в пять секунд; текст и форма волны не записываются.

Не записываются аудиоданные, субтитры, черновики, переводы, ключи API, заголовки авторизации, сырые ответы поставщиков, адреса сервисов, названия пользовательских пресетов и устройств. Рабочие запросы по-прежнему отправляются выбранным сервисам, но диагностика не добавляет передачу журналов в сеть.

Журнал сохранения конфигурации сообщает только о завершении команды, без объекта настроек. Случайные ID запросов не содержат пользовательский ввод, название модели или UID устройства.

## Чтение журнала

Формат — JSON Lines: один JSON-объект на строку. Пример:

```json
{"schemaVersion":1,"timeUnixMs":1792915200000,"uptimeMs":1240,"runId":"example-run","version":"<версия приложения>","platform":"macos","architecture":"aarch64","source":"main","operation":"translate","kind":"start","traceId":"11111111-2222-4333-8444-555555555555","correlationId":"aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeeeee:0"}
{"schemaVersion":1,"timeUnixMs":1792915200600,"uptimeMs":1840,"runId":"example-run","version":"<версия приложения>","platform":"macos","architecture":"aarch64","source":"main","operation":"translate","kind":"error","traceId":"11111111-2222-4333-8444-555555555555","correlationId":"aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeeeee:0","durationMs":600,"reason":"invalid_response"}
```

- `runId` отличает текущий запуск процесса; это не ID аккаунта или устройства.
- `timeUnixMs` — системное время в миллисекундах для сопоставления со снимками экрана; `uptimeMs` — монотонное время с запуска.
- `adapter` — только фиксированный код протокола, например `minimax_tts_ws` или `openai_audio_transcriptions`, без адреса поставщика, модели и голоса.
- `attempt` — номер попытки восстановления соответствующего события прослушивания.
- `traceId` связывает начало и завершение команды от интерфейса к серверной части.
- `correlationId` связывает сеанс прослушивания или задачу отправки; число после двоеточия отличает попытки повторной отправки.
- `durationMs` при завершении команды — её полная длительность; для этапа речи — время с начала запроса; для сводного события — P95 соответствующего процесса. P95 — статистика недавних замеров, а не длительность одного запроса.
- `reason` — фиксированная категория, например `auth`, `quota`, `timeout`, `network`, `device`, `invalid_response`. `unknown` означает, что классифицировать ошибку не удалось; конкретную причину из этого выводить нельзя.

Сначала найдите нужный `runId` и время, затем свяжите этапы по `traceId` или `correlationId`. Если есть только `start`, учитывайте выход, panic, переподключения и снимки экрана. Это само по себе не доказывает сбой поставщика.

## Ресурсы и конфиденциальность

- Запись выполняется отдельным потоком через ограниченный канал на 512 событий. Если запись занята, события отбрасываются, не блокируя аудиозахват и рабочие запросы.
- Размер одного файла — до 1 МиБ; сохраняются текущий и два предыдущих файла, всего около 3 МиБ. Экспорт занимает ещё до 3 МиБ и хранится в одном фиксированном файле.
- Экспорт последовательно выполняется потоком записи, чтобы ротация не нарушала целостность снимка.
- На macOS / Linux права каталога — `0700`, файлов — `0600`. Дополнительного шифрования журналов нет; программы того же системного пользователя с соответствующими правами могут их читать.
- `droppedEvents` в заголовке экспорта — число событий, потерянных при постановке в очередь или записи в текущем запуске. При сбое диска, принудительном завершении или переполнении записи могут быть неполными. Ошибка журналирования не должна мешать использованию приложения.
- Метаданные содержат время операций, версию и этапы использования. Перед отправкой их можно проверить. После удаления исходных журналов соответствующую историю восстановить нельзя.

## Реализация и проверки

- [`src/diagnostics.ts`](../../src/diagnostics.ts): жизненный цикл команд, категории ошибок, этапы речи и сводки прослушивания.
- [`src/core/diagnostics.ts`](../../src/core/diagnostics.ts): фиксированные категории и проверка случайных идентификаторов.
- [`src-tauri/src/diagnostics.rs`](../../src-tauri/src/diagnostics.rs): разрешённые поля и источники, ограниченный канал, команды журналов.
- [`writer.rs`](../../src-tauri/src/diagnostics/writer.rs): права, ротация и последовательный экспорт.
- [Тесты интерфейса](../../src/diagnostics.test.ts) и [нативные тесты](../../src-tauri/src/diagnostics/tests.rs): фильтрация содержимого, исключение исходных ошибок, работа при сбоях журнала, ограничения ротации, объём экспорта и права файлов.

При Rust panic предпринимается попытка сбросить уже поставленные в очередь метаданные за время до 800 мс. Если сбой произошёл в самом потоке записи, он не ожидает себя. Это уменьшает потери при последующем abort нативного обратного вызова, но не гарантирует запись всех системных сбоев. Сообщения panic и стек не сохраняются.
