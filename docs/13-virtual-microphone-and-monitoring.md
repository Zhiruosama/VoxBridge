# VoxBridge 虚拟麦克风与本地试听

2026-10-23：新增 macOS 同名虚拟输入/输出驱动、系统安装器入口、发送设备快捷选择及独立试听开关。安装与卸载步骤见 [驱动说明](../native/macos/virtual-mic/README.md)。默认关闭试听，不自动修改空设备配置。

发送使用一次合成，主路发送至所选设备，本地路播放至试听设备。开关支持合成期间和播放期间切换；请求 ID 隔离，取消仍取消整个任务。试听错误或积压只停止本地副本并提示，不取消发送。流式路径复制已解码 PCM，兼容 HTTP 路径从当前播放位置开始试听，不重播已播放部分。

配置持久化只保存设备 UID 与布尔开关；服务凭证仍是现有会话内存机制，安装不会读取 Keychain。只有主窗口可以打开固定的安装包或切换当前语音任务的试听。安装入口不自动提升权限或安装，管理员操作由系统安装器完成。

## 2026-10-23 真实设备复核

0.1.0 安装后已完成虚拟设备实际回环及应用语音发送测试。最初无声的直接配置原因是发送设备选成外置耳机、试听设备 UID 已失效；通过界面改为发送 VoxBridge、试听外置耳机并保存，保持试听关闭。真实合成测试从虚拟输入收到非零 PCM（峰值 0.29514）。系统默认输入保持外置麦克风。

0.1.1 修正 Chromium 所使用的数据源名及音频流名，统一为 VoxBridge；补命名、可见性、默认输入资格、麦克风终端属性回归测试。名字更新需要安装新驱动；仅重启主应用不会更新系统已加载的驱动。

QQ 问题暂缓：用户截图及重启后的复测均未列出设备，Core Audio / AVFoundation 却可列出；尚无证据确认 QQ 的具体过滤条件。REA 对 QQ 7.0.2 application.asar 的 background.js、preload.js 做了限定静态分析（Evidence `ev_29d0e888365df3ddd07e283b0143648908aa93a8f26e726a36c0e741ddc82c07`，SHA-256 `e515fbf7c47d0e05a5539c9aeeea8a3268551dd5f6ddb7a39a9a4bb656c7bf12`），不覆盖原生音频模块，不能证明过滤行为。未安装额外反编译引擎、未修改 QQ、未改变系统默认输入。按用户要求建立 GitHub issue 跟踪。

## Discord 安装后验收

0.1.1 已由系统安装器升级并重新加载，安装回执与系统输入/输出源均确认名称为 VoxBridge。刷新 Discord 后实际麦克风选项显示 `VoxBridge (Virtual)`，所选 UID 保持不变。升级后实际回环再次通过（48kHz，峰值 0.1，RMS 0.07049）。

Discord 麦克风调试中，用户先报告断续/失真。原配置为自定义、Krisp 降噪和回音抵消开启；切换到“工作室”无处理模式后，用户确认明显改善、整体可听，但仍有少量失真。此为改善而非完全音质验收通过。第二句实际虚拟输入录音约 5.24 秒有效语音，峰值 0.26816，无削波，语音内部未检出 >=16 帧的全零片段；不能据此排除所有失真。用户对原始虚拟输入录音与 Discord 回放未听出明显差别，因此不能把剩余音质问题直接归因于 Discord。没有改动用户的合成音色或语速。

QQ 延后跟踪：https://github.com/Zhiruosama/VoxBridge/issues/1 。系统默认输入保持外置麦克风。Discord 调试留在 VoxBridge + 工作室模式，应用自身试听关闭，避免双重回放。
