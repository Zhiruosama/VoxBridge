## 2. 阶段与退出条件

### M0：文档评审（本轮）

交付：本目录与 README。退出条件：用户 review 范围、技术提案和主要未决项，形成修订意见。文档交付不表示提案已获批准。

### M1：工程骨架与平台可行性

准备主窗口、模块契约、模拟事件与平台条件编译；在 Mac 验证最小原生桥接、指定应用采集、设备输出、BlackHole 路由和权限。

退出条件：Mac 上不依赖 AI，能稳定采集目标声音并向 Discord 输出测试语音；反复启停无资源残留；接收与发送不形成数字回环。若无法实现，则先调整音频方案和文档。

### M2：首个真实端到端原型

连接一家流式 ASR、一家翻译服务与一个 TTS 候选，完成主窗口字幕和文字发送；补足取消、断线、错误恢复。

退出条件：完成[功能 F01–F05](01-requirements.md)，用真实凭据、真实声音和对端回听通过流程；记录延迟和质量基线。模拟通过不能代替此条件。

### M3：可用的 macOS 第一版

加入悬浮字幕、凭据持久化、设备恢复、用量估算和可复现构建说明。

退出条件：F01–F08 验收、30 分钟稳定性冒烟、多次启动与权限恢复通过；关键缺陷已修复，已知限制写入 README。发布给其他用户前另行验证签名、公证与干净环境安装，不以开发机运行替代发布验收。

### M4：增量能力

加入真实麦克风翻译，评测本地 ASR，之后启动 Windows 音频适配。各项独立验收，避免把它们都塞进首次 Mac 联调。

## 3. 需要自动验证的关键行为

工程建立后优先测试有实际故障风险的逻辑：

- ASR 多次 partial / 重复 final，只翻译一次对应定稿。
- 翻译乱序返回、源文本修订、停止后晚到事件，不覆盖新状态。
- 停止发送后旧音频分片不能再次播放；新任务不继承旧缓冲。
- 有界队列溢出会明确降级，不无限堆积；设备丢失不自动切换输出。
- PCM 格式转换使用已知信号验证声道、采样率、时长与振幅，不只检查函数被调用。
- 模拟认证失败、限流、断线和半途 TTS 错误，验证重试与不重复播放。

供应商集成测试需显式启用，默认不调用付费服务，不将真实密钥加入仓库。

## 4. Mac 实机验证矩阵

| 分类 | 用例 | 通过条件 |
| --- | --- | --- |
| 首次权限 | 允许 / 拒绝 / 再授权 | 状态正确，可恢复，无隐式持续采集 |
| 采集对象 | Discord、浏览器、重启、切换子进程 | 对象正确，无声音时不虚构内容 |
| 音频格式 | 内建耳机 / USB / 蓝牙，按现有设备测试 | 格式协商正确，音调和速度正常 |
| 发送路由 | 试听、发送、停止、设备断开 | 路由隔离，无意外扬声器回落 |
| 同时收发 | 对端说话期间发送 TTS | 不识别自身 TTS；对端能听清 |
| 应用处理 | Discord 输入检测与对端通话 | 无明显截断、音量合理 |
| 窗口 | 普通桌面、全屏 Space、多屏、穿透恢复 | 可见、可控，无失去控制的窗口 |
| 生命周期 | 连续启停 20 次、退出、睡眠唤醒 | 无残留播放 / 采集 / 系统对象 |
| 异常网络 | 超时、断线、恢复、余额不足 | 状态可见，不无界重试 |
| 稳定性 | 30 分钟真实声音处理 | 无崩溃、队列持续增长或重复播放 |

首测系统不能覆盖最低 14.2 时，最低版本仍为设计目标而非已验证支持。Intel、多语言、不同蓝牙设备等未测项明确标记，不据单一 Mac 推断全部兼容。

## 6. 风险与优先处理

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 原生桥接或权限不通 | 所有接收功能阻塞 | M1 最先验证，不先投入复杂 UI |
| 应用多进程归属不准 | 无声或采错对象 | 专项验证 Discord 与浏览器；必要时调整选择模型 |
| 无虚拟设备 | 无法向聊天软件发声 | 字幕可独立使用，配置引导明确 |
| 模型定稿慢 / 网络波动 | 译文落后 | 分解指标，短句策略，显式降级 |
| 不同供应商 API 约定不一致 | 分片与取消失效 | 窄适配器、协议样例和集成验证 |
| Windows 准备造成错误信心 | Mac 联调集中暴露问题 | 模拟与实机结果分开记录 |
